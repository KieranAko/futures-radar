# 实验线架构设计方案（v5）—— 完整映射 + V1-V8 成果吸收

> 定位：实验线 = 生产线的完整映射实例（测试版本）；前瞻实验在实验线整链做，
> 验证后以"环节段"为单位整段搬回生产线。
> v5 增量：把 V1-V8 的全部实验线成果盘点、归位并吸收进本架构，不允许放弃历史。
> 状态：方案阶段，未实现。

---

## 0. 架构目标

实验线是生产线的同构镜像（staging）。两线共享同一管道蓝图与环节契约，差异只在
"当前启用的配置集合"。V1-V8 的历史成果全部按"环节"归位：已成为生产 stable 的、
作为 candidate 继续实验的、作为基础设施复用的、作为反例禁用的——四类各得其所。

## 1. 设计原则

P1-P6 沿用 v4：
- P1 同构：实验线是生产线的完整映射实例，不是组件；
- P2 环节对：每环节 stable/candidate 双配置，实验只动 candidate；
- P3 回放基线：实验线能整链回放 stable，复现生产产出；
- P4 前瞻实验在整链上做，不做旁路；
- P5 整段搬迁，不搬碎片；
- P6 实验隔离：实验线产物永不直接进入生产报告。

v5 新增：
- **P7 成果归位**：任何历史成果必须归入四类之一——生产 stable / 环节 candidate /
  镜像基础设施 / 反例（禁止模式）；归不进去的即退役。吸收是"归位"不是"保留文件"。

     ┌───────────▼────────────┐                  ┌────────────────▼───────────────┐
     │ 生产线（production）    │◄── promote ──────│ 实验线（experiment / staging）  │

## 4. 成果归位规则（P7 展开）

| 归位类别 | 判定 | 动作 |
|---------|------|------|
| 生产 stable | 已被生产采纳且仍在运行 | 保留，进入两线逐字节一致的 stable 配置 |
| 环节 candidate | 未搬回但有前瞻价值 | 挂到对应环节，作为实验配置进入 register 队列 |
| 镜像基础设施 | 不是业务配置，是"实验线作为镜像"的工程件 | 复用（V7 adapter、V8 runner），并作为 P3 基线设施 |
| 反例 | 被否决/作废的架构或方法 | 写入 ADR 禁止模式，代码归档不复活 |
| 退役 | 归不进以上四类 | 归档，不进入新架构 |

## 5. promote 的参考实现（V1-V8 已跑通一次）

V7 蓝图 → 生产 analyze，是本项目唯一一次完整"环节段搬迁"，它证明 P5 可行；
V7 strategy-plan-adapter 证明"实验线以生产 runDir 同构方式原样调用生产环节"可行（P1 的工程可行性）；
V8 runner 证明"只读生产 strategy-plan 的 T+1 语义执行"可行（P3/P4 的执行基础）。
这三件事合起来就是 v5 实施路径的三块现成积木：
**镜像 = V7 adapter 模式；回放 = V8 runner 模式；搬迁 = V7 蓝图模式。**

## 6. 架构决策记录（ADR）

- AD-1 实验线是生产线的完整映射实例，不是组件（P1）；
- AD-2 每环节一对配置（stable/candidate），实验只动 candidate（P2）；
- AD-3 一切前瞻实验必须先在完整管道内回放+影子，不做旁路（P4）；
- AD-4 promote 单位是完整环节段，禁止跨环节拼装（P5）；
- AD-5 可信度是报告环节的 candidate 模型，验证对象是校准度（§3.6 基线数据）；
- AD-6 实验线产物永不直接进入生产报告（P6）；
- AD-7 历史成果按四类归位，不归位即退役（P7）；
- AD-8 禁止模式：旁路实验不绑定公式（V9 教训）、后置定价层（pricing-layer-v8 教训）。

## 7. 实施边界（本阶段）

- 本方案不包含任何实现；
- 若批准，第一步：**建立管道镜像**，且该步骤必须复用两块历史积木——
  用 V7 strategy-plan-adapter 的 runDir 同构模式搭镜像骨架，
  用 V8 runner 的执行语义做 stable 回放基线验证；
  镜像未建立前不讨论任何新实验。
