# 实验线架构设计方案（v4）—— 生产线完整映射

> 定位纠正（v3 作废）：实验线**不是生产线的一个组件或供应商**，而是**生产线的完整映射**——
> 一个测试版本。在实验线做前瞻性实验研究，验证通过后把实验线的环节**整段搬回生产线**。
> 状态：方案阶段，未实现。

---

## 0. 架构目标（一句话）

实验线 = 生产线的**同构镜像实例**（staging）：同一条管道蓝图、同一套环节、同一份代码与数据接口。
实验线内可以打开实验开关做前瞻研究（新机制、新数据、新可信度模型），验证通过后以
"环节段"为单位整段搬回生产线（promote）；生产线自身永远只跑已验证配置。

## 1. 设计原则

- **P1 同构**：实验线与生产线共享同一份管道蓝图（数据获取 → 筛选 → FinCoT 推理 → 概率 →
  策略适配 → 报告）。任何生产环节在实验线都有完整对应物，缺一不可。
- **P2 环节对（stage pair）**：每个环节同时存在两份配置——`stable`（生产在跑）与
  `candidate`（实验在试）。实验只发生在 candidate 配置上，stable 配置在生产与实验线
  中保持逐字节一致。
- **P3 回放基线**：实验线能用历史数据整链重跑 stable 配置，复现生产当时产出
  （01-L3：回测是审判——先有可复现基线，才谈实验）。
- **P4 前瞻实验在整链上做**：任何实验（新机制、新数据源、新蓝图、新可信度模型）都是
  挂在管道某环节上的 candidate 配置，并在**完整管道**内运行验证，不做脱离管道的旁路。
- **P5 整段搬迁，不搬碎片**：验证通过后，把该环节的 candidate 配置连同其数据契约、
  测试、文档整体提升为 stable（promote）；不通过则丢弃 candidate。
  生产线不吸收"结论"，只吸收"经过验证的环节段"。
- **P6 实验隔离**：两线独立 runDir/数据快照/报告输出；实验线产物永不直接进入生产报告。

## 2. 架构总图

```
                 ┌──────────────── 管道蓝图（唯一架构） ────────────────┐
                 │  数据获取 → 筛选 → FinCoT 推理 → 概率 → 策略适配 → 报告 │
                 └─────────────────────────────────────────────────────┘
        stable 配置                                        candidate 配置
        （已验证，逐字节一致）                                （前瞻实验）
                 │                                                │
     ┌───────────▼────────────┐                  ┌────────────────▼───────────────┐
     │ 生产线（production）    │                  │ 实验线（experiment / staging）  │
     │ 每日自动跑 stable      │◄── promote ──────│ 回放 stable 建立基线            │
     │ 输出当日报告与策略      │   整段搬回         │ 打开 candidate 跑前瞻实验       │
     │ 人读报告做决策          │                  │ 影子对比、前向记录、证据积累    │
     └────────────────────────┘                  └────────────────────────────────┘
```

两线是同一蓝图的两个实例，不是两个系统。差异只在"当前启用的配置集合"。

## 3. 环节与两线配置对照（概念级）

| 管道环节 | stable 配置（两线一致） | candidate 配置（实验线前瞻） |
|---------|----------------------|---------------------------|
| 数据获取 | 现有 collect/macro/sector 字段集 | GA-8 基差历史接入、新数据源、新质量门 |
| 候选筛选 | 波动率/流动性筛选规则 | 机制驱动的状态筛选（如 carry 分层筛选） |
| FinCoT 推理 | 现有 BP-* 蓝图 + 门禁 | 机制识别步骤：从机制目录匹配适用机制，替代/增强 BP-* 启发式 |
| 概率 | Yang-Zhang 锥（现状） | 不变或按机制补充（如基差收敛分布） |
| 策略适配 | strategy-library v1 规则库 | 机制实例模板 + 证据约束（v2 档案改造后的候选） |
| 报告/可信度 | FinCoT 自报 confidence（现状） | 三层可信度模型（族级证据×状态匹配×实现保真），D11 架构化落地 |
| 前向记录 | 无 | 计划→结果归因账本（01-L7：策略会被审判） |

每个 candidate 的启用/关闭是实验线的一个 feature flag；每对环节共用一份接口契约。

## 4. 前瞻实验生命周期

```
register（注册 candidate 配置：机制/数据/模型 + 可证伪命题 + 判决规则 + 时间盒）
   → replay（实验线回放 stable 基线，再回放 candidate，比较差异）
   → shadow（实验线与生产线并行前向跑 candidate，影子模式，积累前向记录）
   → review（按预注册规则判决：promote / revert / 延期一次）
   → promote（candidate → stable，整段搬回生产线；生产线与实验线再次逐字节一致）
```

- 判决规则引用 24 协议纪律（预注册、α、seed），并追加时间盒（01-L3/L4）。
- 回放与影子阶段产生的全部证据进入该环节的证据账本，随 promote 一起搬回。

## 5. 搬迁协议（promote 的边界）

1. 搬迁单位 = **一个完整环节段**：环节配置 + 数据契约 + 测试 + 证据账本 + 文档；
2. 禁止跨环节拼装（不允许"实验线的筛选 + 生产线的适配"这种混合体进入生产）；
3. promote 前必须通过：回放复现基线一致 + 前瞻证据达标 + 全管道端到端测试；
4. promote 后：生产切到新 stable；实验线重建与生产一致的 stable 副本；
5. revert：新 stable 出问题时，整段回滚到上一 stable（版本化）。

## 6. 与核心目标的关系

- **有效分析**：FinCoT 环节的 candidate = 机制识别增强，验证对象就是"分析是否有效"
  （回放历史报告 vs 事后行情，P3）；
- **合理策略**：策略适配环节的 candidate = 机制实例模板，验证对象就是"策略是否有效"；
- **策略可信度**：报告环节的 candidate = 三层可信度模型，验证对象就是"可信度是否校准"
  （影子阶段比较可信度评级与实际结果）；
- **人做决策**：生产报告结构不变，只是可信度字段从自报升级为证据合成——对人只增强可读性。

## 7. 现有资产处置

| 资产 | 处置 |
|------|------|
| 生产线管道代码（pipeline/collector/scanner/filter/analyze/probability/report/matcher） | 保留为 stable 配置的实现 |
| GA-1..GA-8 数据与质量门 | 数据获取环节的 candidate 资产（GA-8 基差待 promote） |
| falsification harness + spec + adapter | 策略适配环节的实验验证工具，并入实验线回放/影子设施 |
| 机制探针 + 机制假设 | FinCoT/策略适配环节的 candidate 注册来源 |
| strategy-library-v2 八条目及判决 | 转为"机制实例档案"，作为策略适配 candidate 的证据输入 |
| strategy-library v1 | 生产 stable 配置（现状），等待策略适配 candidate 通过后整体替换 |
| theory-base | 保留为机制注册与可信度模型的理论依据源（P5 内容根） |
| 23/24 协议 | 并入实验生命周期（register/review 的判决纪律） |

## 8. 架构决策记录（ADR）

- **AD-1** 实验线是生产线的完整映射实例，不是组件（P1）；
- **AD-2** 每环节一对配置（stable/candidate），实验只动 candidate（P2）；
- **AD-3** 一切前瞻实验必须先在完整管道内回放+影子，不做旁路（P4）；
- **AD-4** promote 单位是完整环节段，禁止跨环节拼装（P5）；
- **AD-5** 可信度是报告环节的 candidate 模型，验证对象是"校准度"而非"是否好看"（§6）；
- **AD-6** 实验线产物永不直接进入生产报告（P6）。

## 9. 实施边界（本阶段）

- 本方案不包含任何实现；
- 若批准，第一步建议：**先建立管道镜像**——把生产线完整复制为实验线实例
  （同一蓝图、同代码、独立 runDir、回放 stable 基线通过），镜像未建立前不讨论任何实验。
