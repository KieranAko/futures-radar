# 实验线架构设计方案（v3）

> 定位：实验线是从生产线抽离出来做实验的产物；本方案定义它的新架构。
> 依据：theory-base 四份吸收报告 + 全流程有效性分析结论（三个缺口/核心矛盾）。
> 状态：**方案阶段，未实现**。任何实现须经队长批准后按本方案分阶段进行。

---

## 0. 架构目标（一句话）

把实验线从"验证策略条目的批处理判决器"，改造为**生产线的证据与可信度供应商**：
生产线做分析（FinCoT）与策略适配（matcher）时，从实验线获取"机制命题 + 证据强度 + 实例可信度"，
而不是自己发明规则、自报置信度。

## 1. 设计原则（全部来自理论库，逐条可回溯）

- **P1 机制是第一实体，策略是实例**（01-L1/L2、02-T1~T4、03-S3、04-R2）。
  系统围绕"收益来源机制"组织；策略只是机制在特定品种、状态、参数下的实例化。
- **P2 便宜证伪优先，判决先于实验**（01-L3/L4）。
  每个机制从最便宜的命题检验开始，逐级投入；每级实验前写死 go/no-go 与时间盒。
- **P3 证据持续累积，没有一次性终审**（01-L7、04-R3）。
  机制的证据账本持续更新；时变状态（溢价强弱、政策窗、半衰期漂移）是机制的一等属性。
- **P4 可信度分层合成，禁止单层虚报**（04-R2、01-L3）。
  可信度 = 族级证据 × 实例状态匹配 × 实现保真；FinCoT 自报不得替代。
- **P5 内容以期货第一性为根**（02-T1~T4）。
  carry/展期/基差是首选机制族；其他族必须通过来源检查（04-R1 三分类）。
- **P6 架构必须可移植回生产线**（项目目标）。
  实验线的对外产物定义清楚"生产消费协议"，本阶段只冻结协议概念，不实现。

## 2. 第一实体：机制（Mechanism）

### 2.1 机制条目（概念字段）

| 字段 | 内容 |
|------|------|
| id / name / family | family ∈ {carry, value, momentum, volatility, liquidity, behavioral-friction}（04-R1/R2） |
| theoryRef | theory-base 报告编号 + 章节 + 命题（强制） |
| proposition | 可证伪 H0/H1 |
| whyItWorks | 机制逻辑：为什么赚钱、为什么没被套利掉（04-R2 四问） |
| applicableStates | 状态变量与取值域（趋势态/库存态/波动态/政策窗/交割距离） |
| timeScale | 半衰期或持有期范围（02：半衰期先于持有期） |
| invalidation | 结构性失效 vs 状态性失灵（区分两者，04-R3） |
| evidenceLedger | 指向证据账本条目 |
| lifecycle | candidate → probing → state_validated → retired（状态级） |

### 2.2 策略实例（Strategy Instance）降为实例

| 字段 | 内容 |
|------|------|
| mechanismId | 绑定机制 |
| universe / dataContract | 品种集与数据需求（数据契约按机制需求注册，P5） |
| params | 参数（少、强度制优先，03-S3/S4） |
| fidelity | 实现保真级别（23 F-A..F-H 结果） |
| instanceEvidence | 该实例的实验证据 |
| lifecycle | derived → backtested → validated → deprecated |

实例退役 ≠ 机制死亡；实例死亡不写进机制层（TR-01 案例：实例 gate_failed，机制记录留档）。

## 3. 分层架构

```
L0 数据层（保留既有 GA-1..GA-8 + 数据契约 + 质量门）
   新增纪律：每个采集字段必须被至少一个已注册机制消费（无消费者即裁剪）
L1 机制库（新，替代"策略库为第一实体"）
   机制条目 + 理论绑定 + 适用状态空间
L2 证据引擎（新核心）
   G1 命题检验 → G2 机制级回测 → G3 实例级回测 → G4 前向记录回流
L3 证据账本（新）
   族级汇总 + 状态化更新 + 可信度计算
L4 适配协议（只定义，不实现）
   实验线对生产线的只读接口：机制目录 / 证据账本 / 可信度服务
L5 报告消费（生产线已有，仅定义可信度字段的语义）
```

## 4. 证据分级漏斗（L2 核心）

| 级别 | 实验内容 | 成本 | 判决规则（写死） |
|------|---------|------|-----------------|
| G1 命题检验 | 机制命题的最便宜统计检验（如 z 阈值后方向收益、半衰期估计、分层收益） | 最低 | 默认淘汰；明显超成本线才升 G2；证据不足=pending（限一次，超时退役） |
| G2 机制级回测 | 族级/分层组合收益，不建完整策略；半衰期匹配持有期 | 低 | 按族级证据表判定；状态分段报告 |
| G3 实例级回测 | 完整五段实例 + 保真 F-A..F-H + walk-forward | 高 | 只对 G2 存活者开放；判决=实例级（validated/deprecated） |
| G4 前向记录 | 生产线策略计划的 PIT 记录与归因回流 | 极低（天然产生） | 持续更新实例与机制证据，触发降级/退役 |

关键变化：现有 falsification harness 降级为 G3 引擎（保留）；机制探针降级为 G1 工具（保留）；
**先 G1/G2 后 G3 的漏斗顺序成为硬约束**。

## 5. 可信度模型（L3）

```
可信度 = f(族级证据, 实例状态匹配, 实现保真)
```

| 成分 | 来源 | 含义 |
|------|------|------|
| 族级证据 | 证据账本：该族在样本内的 n、CI、状态分段、政策窗分段 | 机制这类收益历史上存在吗、多强 |
| 状态匹配 | 当前市场状态 vs 机制的 applicableStates | 机制现在"在场"吗 |
| 实现保真 | 该实例的 F-A..F-H 结果 | 测的是不是真机制 |

输出四档（A/B/C/D）+ 依据明细（人读）。任何一档必须列出三条成分的具体取值；
**禁止用 FinCoT 自报 confidence 代替**（D11 的架构化落实）。

## 6. 与生产线的对接（只冻结协议概念）

实验线对外只暴露三个只读产物：

1. **机制目录**：当前有效的机制条目 + 各自适用状态空间（供生产 FinCoT 推理时识别"当前该用哪个机制"）；
2. **证据账本**：族级/实例级证据与最近更新（供报告"可信度"字段引用）；
3. **可信度服务协议**：输入（品种+当前状态快照）→ 输出（适用机制实例模板 + 三层可信度明细）。

生产线的将来改造点（不在本方案范围内实现，仅标注）：
- FinCoT 推理增加"机制识别"步骤：从机制目录中匹配，而不是从 BP-* 启发式自选；
- strategy-matcher 的输入从 v1 规则库改为"机制实例模板 + 证据约束"；
- 报告"置信度"字段改为"可信度评级 + 证据依据"。

## 8. 架构决策记录（ADR，概念级）

- **AD-1** 机制为第一实体，策略为实例（P1）；
- **AD-2** 证据分级漏斗是唯一升级路径，G1→G2→G3 不可跳级（P2）；
- **AD-3** 可信度三层合成，单层缺数据时可信度必须降档而不是虚报（P4）；
- **AD-4** 时变状态是机制的属性，证据账本按状态分段维护（P3）；
- **AD-5** 实验线与生产线只以"机制目录/证据账本/可信度协议"对接（P6）；
- **AD-6** 组合层与仓位决策不在实验线内实现，归属人决策与执行侧（项目边界）。

## 9. 方案自检（本方案是否回答了三个缺口）

| 缺口 | 本方案的对应 |
|------|-------------|
| 横断面：机制命题层缺失 | L1 机制库 + theoryRef 强制 + 来源族必填（P1/P5） |
| 纵断面：审判闭环缺失 | L2 证据引擎 G4 前向回流 + 证据账本持续更新（P3） |
| 连接面：两库对象断裂 | L4 适配协议 + v1 规则库退役路径 + 机制实例模板（P6/AD-5） |

## 10. 实施边界（本阶段）

- 本方案**不包含任何实现**：不建机制库、不改 harness、不动生产 matcher；
- 下一步若获批准，建议的第一个动作是：用两个现有案例（TR-01→momentum 族档案、FS-02→carry 族 G1/G2 流程）做**纸面走查**，验证新架构的实体与流程能容纳既有证据，再谈编码。
